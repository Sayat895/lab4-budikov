# Автоматизация учета работы филиала

Учебное desktop-приложение для учета сотрудников, филиалов и смен. Интерфейс реализован на React и открывается в отдельном системном окне через WebView — браузер для работы не нужен. Python REST API взаимодействует с PostgreSQL.

## Запуск в Windows

Необходимы Python 3.12, Node.js LTS, Docker Desktop и установленный Microsoft Edge WebView2 Runtime.

1. Создайте локальный файл конфигурации и задайте собственные пароли:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

   Замените `replace-with-a-private-...` на пароли PostgreSQL, руководителя и старшего кассира. `.env` исключен из Git.

2. Запустите PostgreSQL:

   ```powershell
   docker compose up -d db
   ```

3. Установите зависимости и соберите интерфейс:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r app\requirements.txt
   npm --prefix app\frontend ci
   npm --prefix app\frontend run build
   ```

4. Один раз настройте HTTPS-сертификат приложения:

   ```powershell
   python app\setup_https.py
   ```

   Скрипт создаёт локальный сертификат для `127.0.0.1` и `localhost`, ограничивает доступ к закрытым ключам текущим пользователем Windows и добавляет корневой сертификат в доверенное хранилище **текущего пользователя**. Права администратора не нужны. Ключи хранятся вне репозитория в каталоге `Lab4Budikov\tls` в локальных данных текущего пользователя; повторный запуск проверяет и переиспользует действующие сертификаты.

5. Откройте desktop-приложение:

   ```powershell
   python app\main.py
   ```

Окно приложения открывается отдельно от браузера. API принимает соединения только на loopback-адресе и использует HTTPS. Для остановки закройте окно приложения; PostgreSQL продолжит работать в Docker. Остановить базу можно командой `docker compose down`; данные сохраняются в Docker-томе `pg_data`.

Для разработки интерфейса запустите Vite в отдельном терминале:

```powershell
npm --prefix app\frontend run dev
```

Для запуска приложения всегда используйте собранную версию (`npm --prefix app\frontend run build`).

## Возможности

- **Обзор:** активные сотрудники, смены за сегодня и за месяц, кассовые недостачи, излишки и смены без отклонений.
- **Сотрудники:** руководитель создает, изменяет и удаляет карточки персонала, указывает филиал, должность и статус.
- **Смены:** сотрудник может зарегистрировать смену своего филиала; руководитель может просматривать и изменять смены всех филиалов.
- **Филиалы:** руководитель управляет филиалами.
- **Отчеты:** экспорт смен и списка сотрудников в Excel за выбранный период и филиал; старший кассир ограничен своим филиалом.
- **Роли:** доступ и область данных проверяются REST API, а не только скрытием элементов интерфейса.
- **Горячие клавиши:** `Ctrl+R` обновляет данные, `Ctrl+Q` завершает сеанс.

## Структура

| Компонент | Назначение |
|---|---|
| `app/main.py` | Создание REST API и запуск native WebView-окна |
| `app/controllers/` | REST-контроллеры авторизации, обзора, филиалов, сотрудников, смен и отчетов |
| `app/db.py` | Подключение к PostgreSQL, схема и операции с данными |
| `app/frontend/src/` | React-интерфейс и REST-клиент |
| `docker-compose.yml` | Локальный PostgreSQL с постоянным Docker-томом |

REST API доступен только на `127.0.0.1:8000` через HTTPS. OpenAPI-документация доступна по адресу `https://127.0.0.1:8000/docs`, пока запущено приложение.

Пароль при входе передаётся только внутри TLS-зашифрованного HTTPS-соединения. В базе пароль не хранится в открытом виде: используется PBKDF2-HMAC-SHA256 с уникальной случайной солью и 310 000 итерациями. Не отключайте проверку сертификата и не запускайте приложение без локальной настройки HTTPS.

## REST API: запросы и ответы

Все JSON-маршруты находятся под префиксом `/api`. Для запросов с телом используйте `Content-Type: application/json`. После входа добавляйте заголовок `Authorization`: укажите в нем схему `Bearer`, пробел и значение `access_token` из ответа входа. Списки возвращаются как JSON-массивы; даты представлены строками `YYYY-MM-DD`.

Проверка доступности без авторизации: `GET /api/health` возвращает `200 OK` и `{"status": "ok"}`.

### Авторизация

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `POST /api/auth/login` | Без токена | Вход |
| `GET /api/auth/me` | Требуется токен | Текущая учетная запись |
| `POST /api/auth/logout` | Требуется токен | Завершение сеанса; успешный ответ `204 No Content` без JSON-тела |

`POST /api/auth/login` принимает:

```json
{
  "username": "director",
  "password": "your-password"
}
```

Успешный ответ `200 OK`:

```json
{
  "access_token": "opaque-session-token",
  "token_type": "bearer",
  "user": {
    "id": 1,
    "username": "director",
    "role": "Руководитель",
    "branch_id": null
  }
}
```

Для старшего кассира `branch_id` содержит ID назначенного филиала. `GET /api/auth/me` возвращает тот же объект `user`, без обертки. Неверные учетные данные дают `401`:

```json
{"detail": "Неверный логин или пароль."}
```

### Обзор

`GET /api/dashboard?branch_id=1` возвращает количество активных сотрудников, смен и сумм за месяц, а также количество смен за сегодня. Для руководителя `branch_id` необязателен: без него сводка охватывает все филиалы. Старший кассир всегда получает сводку только своего филиала.

```json
{
  "employees": 12,
  "shifts": 84,
  "today_shifts": 3,
  "shortage": 1250.0,
  "surplus": 300.0,
  "shortage_shifts": 2,
  "surplus_shifts": 1,
  "no_deviation_shifts": 81
}
```

`shortage` и `surplus` — суммы по сменам с начала текущего календарного месяца; поля `*_shifts` — количество соответствующих смен.

### Филиалы

| Метод и путь | Доступ | Успех |
|---|---|---|
| `GET /api/branches` | Любая роль | `200`, массив филиалов |
| `POST /api/branches` | Только руководитель | `201`, сообщение |
| `PUT /api/branches/{branch_id}` | Только руководитель | `200`, сообщение |
| `DELETE /api/branches/{branch_id}` | Только руководитель | `204`, без тела |

Формат филиала в ответе `GET`:

```json
{
  "id": 1,
  "name": "Центральный",
  "address": "ул. Примерная, 1"
}
```

Тело `POST` и `PUT`:

```json
{
  "name": "Центральный",
  "address": "ул. Примерная, 1"
}
```

Ответы на создание и изменение: `{"message": "Филиал добавлен."}` и `{"message": "Данные филиала обновлены."}`. Руководителю возвращаются все филиалы, кассиру — только назначенный. Пустое название отклоняется; совпадающее название даёт `409 Conflict`. `name` обязателен, после удаления пробелов не может быть пустым и ограничен 200 символами; `address` необязателен и ограничен 500 символами.

### Сотрудники

| Метод и путь | Доступ | Назначение и успешный ответ |
|---|---|---|
| `GET /api/employees?branch_id=1` | Любая роль только в доступных филиалах | `200`, массив сотрудников; кассиру возвращаются только сотрудники его филиала |
| `GET /api/employees/branch/{branch_id}` | Любая роль в пределах своего филиала | `200`, список сотрудников для выбора в смене; старшему кассиру — только его должностная группа |
| `POST /api/employees` | Только руководитель | `201`, `{"message": "Сотрудник добавлен."}` |
| `PUT /api/employees/{employee_id}` | Только руководитель | `200`, `{"message": "Данные сотрудника обновлены."}` |
| `DELETE /api/employees/{employee_id}` | Только руководитель | `204`, без тела |

Элемент списка `GET /api/employees`:

```json
{
  "id": 10,
  "branch_id": 1,
  "full_name": "Будиков Саят",
  "position": "Продавец",
  "phone": "+77001234567",
  "status": "Работает",
  "active": true,
  "branch": "Центральный"
}
```

`GET /api/employees/branch/{branch_id}` возвращает упрощенные объекты только работающих сотрудников. Старший кассир получает только должности «Кассир дневной», «Кассир ночной», «Продавец-кассир СП дневной» и «Продавец-кассир СП ночной» (существующая должность без уточнения смены «Продавец-кассир СП» также считается дневной). Руководитель получает всех работающих сотрудников филиала:

```json
[
  {"id": 10, "full_name": "Будиков Саят", "position": "Продавец"}
]
```

Тело `POST` и `PUT`:

```json
{
  "branch_id": 1,
  "full_name": "Будиков Саят",
  "position": "Продавец",
  "phone": "+7 (700) 123-45-67",
  "status": "Работает"
}
```

`branch_id` — обязательный ID существующего филиала; `full_name` и `position` обязательны и ограничены 200 символами каждый. Телефон обязателен: API принимает казахстанский номер с кодом `+7` (также преобразует национальный префикс `8`) и хранит его в нормализованном формате `+7XXXXXXXXXX`. Статус обязателен и должен быть одним из значений `Работает`, `В отпуске`, `На больничном`, `Не работает`. Поле `active` в ответе сохранено для совместимости и равно `true` только для статуса `Работает`. В смену можно назначить только сотрудника со статусом `Работает`.

Экран сотрудников доступен обеим ролям: руководитель видит все филиалы и может изменять карточки, старший кассир видит только свой филиал в режиме чтения. Ограничение повторно проверяется сервером и не зависит от интерфейса. Телефонные номера в демонстрационной базе — синтетические; замените их реальными контактами только при наличии разрешения сотрудников.

### Смены

| Метод и путь | Доступ | Назначение и успешный ответ |
|---|---|---|
| `GET /api/shifts?start_date=2026-01-01&end_date=2026-01-31&branch_id=1` | Любая роль в пределах доступных филиалов | `200`, массив смен |
| `POST /api/shifts` | Любая роль в пределах своего филиала | `201`, `{"message": "Смена сохранена."}` |
| `PUT /api/shifts/{shift_id}` | Только руководитель | `200`, `{"message": "Смена сохранена."}` |
| `DELETE /api/shifts/{shift_id}` | Только руководитель | `204`, без тела |

Для `GET /api/shifts` даты необязательны: по умолчанию `end_date` — сегодня, а `start_date` — дата 30 дней до неё (обе даты включены). Переданный диапазон также включает обе даты; если `start_date` позже `end_date`, ответ — `422`.

Элемент массива смен:

```json
{
  "id": 42,
  "branch_id": 1,
  "employee_id": 10,
  "work_date": "2026-01-15",
  "shift_name": "Дневная",
  "hours": 8.0,
  "shortage": 0.0,
  "surplus": 0.0,
  "notes": "",
  "branch": "Центральный",
  "employee": "Будиков Саят",
  "created_by": "director"
}
```

Тело `POST` и `PUT`:

```json
{
  "branch_id": 1,
  "employee_id": 10,
  "work_date": "2026-01-15",
  "shift_name": "Дневная",
  "hours": 8,
  "shortage": 0,
  "surplus": 0,
  "notes": ""
}
```

`employee_id` можно передать как `null` или опустить; `shortage`, `surplus` и `notes` по умолчанию равны `0`, `0` и `""`. Допустимая продолжительность — от 0 до 24 часов. Сотрудник должен быть активным и относиться к выбранному филиалу. Старший кассир может регистрировать смены только для разрешенных должностей в своем филиале; попытка назначить сотрудника другой должности отклоняется с `403`. Руководитель не ограничен этим списком.

`branch_id`, `work_date`, `shift_name` и `hours` обязательны. `shift_name` ограничен 100 символами, `notes` — 2000 символами; значения `hours`, `shortage` и `surplus` не могут быть отрицательными.

### Excel-отчет

`GET /api/reports/shifts.xlsx?start_date=2026-01-01&end_date=2026-01-31&branch_id=1` требует обе даты. Ответ `200` — не JSON, а файл XLSX (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`) с листами «Смены» и «Сотрудники». Имя файла передается в заголовке `Content-Disposition`. Область данных для кассира ограничена его филиалом; для руководителя параметр `branch_id` необязателен.

### Ошибки и ограничения доступа

Ошибки API возвращаются в формате JSON:

```json
{"detail": "Требуется авторизация."}
```

- `401 Unauthorized` — отсутствует или завершен сеанс; войдите снова.
- `403 Forbidden` — недостаточно прав либо запрошен чужой филиал. Изменять сотрудников и филиалы, а также менять и удалять смены может только руководитель.
- `404 Not Found` — запрошенный филиал не найден при его изменении или удалении.
- `409 Conflict` — филиал с таким названием уже существует либо запись нельзя удалить из-за связанных данных.
- `422 Unprocessable Entity` — некорректные поля, даты, диапазон дат или ссылка на несуществующий филиал/неактивного сотрудника.

При ошибке проверки входных полей FastAPI возвращает `detail` в виде массива с указанием места и причины:

```json
{
  "detail": [
    {
      "loc": ["body", "hours"],
      "msg": "Input should be less than or equal to 24",
      "type": "less_than_equal"
    }
  ]
}
```
